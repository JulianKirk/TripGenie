# AI-off evidence for the deployed cloud profile (21 Oct 2026)

Refs #171. This file is based on two sources:

- **Deployed settings.** A read-only `az containerapp show` was run on the
  five student backends after
  [run 39580927565](https://github.com/YourNightmareIsOver/TripGenie/actions/runs/39580927565)
  (image `188951a…`). Only the AI, RAG and MCP environment variables listed
  below were read.
- **Source code.** The code on `main` at `188951a`.

**No live AI, RAG or MCP request was made for this file.** The only
AI-related live check is the workflow's Student 1 RAG panel check, which
returned 503.

## Three different states

The checks show three states, which this file keeps separate:

1. **Disabled by configuration.** A flag or a missing URL makes the code
   refuse the feature before it tries the network.
2. **Unreachable.** The URL is set to `http://host.docker.internal:…`. That
   host exists for local Docker Desktop but not in Azure Container Apps, so a
   request would fail and the code should report the dependency as
   unavailable. **This was not exercised live.**
3. **Still visible in the UI.** The frontends still render the AI, RAG and MCP
   controls. Work to hide them is not merged or deployed.

The deployed list of 18 apps contains no AI-Mode, Ollama, MCP server, RAG
server, Multi-Agent Server or agentic loop. Nothing in Azure serves the
`host.docker.internal` URLs. No external model endpoint appeared among the AI
settings that were read.

## What this does and does not prove

- **Proved.** The cloud has no AI services. RAG and MCP are switched off by
  flags for Students 1, 3, 4 and 5. Student 2's AI and RAG URLs are not
  configured. The Student 4 assistant is switched off. Student 1's RAG
  returned 503 live.
- **Not proved.** The direct AI-Mode paths for Student 1 suggestions, Student 3
  suggestions and Student 5 budget analysis are not switched off by
  configuration. They point at an address that does not exist in Azure. Their
  "unavailable" handling was not exercised live, deliberately, to avoid any AI
  call.
- **Not deployed.**
  - [PR #190](https://github.com/YourNightmareIsOver/TripGenie/pull/190) is
    open, with its CI passing, but it is not merged or deployed.
    - It lets Compose pass a blank Student 1 AI-Mode URL, and it blanks that
      URL in `.env.cloud`.
    - The Azure renderer then omits the variable, so the backend defaults to
      AI off.
    - `/api/ai-features` would drive whether the Student 1 UI shows AI
      controls.
    - RAG and MCP keep their own flags.
    - Until it is merged *and* a new deployment is authorised, the deployed
      Student 1 URL stays the hard-coded host-only address shown above.
  - Draft PR #189 (Multi-Agent) is not merged.
  - Neither of these is part of the deployed state above.

# Student 1 Release 0 demo runbook

Target Student 1 segment: **90 seconds maximum** within the group video, whose
total published duration must not exceed ten minutes.

This is a capture plan, not evidence that the demonstration or showcase
participation occurred.

## Before recording

1. Complete the Compose, health, CRUD, and approved-model capture procedure in
   [the evidence directory](evidence/student-1/README.md).
2. Use a disposable demonstration record and know its identifier.
3. Open the shared portal, Student 1 trip page, successful
   [Student 1 CI run](https://github.com/JulianKirk/TripGenie/actions/runs/33764177551),
   and successful
   [AI-Mode CI run](https://github.com/JulianKirk/TripGenie/actions/runs/33764177488).
4. Confirm the real AI result is visible. Do not substitute a screenshot or
   scripted response if Ollama is unavailable.
5. Rehearse once with a timer and coordinate the hand-off with the group.

## 90-second script

| Time | Demonstration |
| --- | --- |
| 0:00–0:08 | Aaditya states name, Student 1 role, and “Trip & Itinerary Management.” This becomes participation evidence only after it is recorded and published. |
| 0:08–0:18 | Start at the shared portal and open the Student 1 frontend, showing integration into the group application. |
| 0:18–0:53 | Create a trip, open it, add an itinerary item, edit one visible field, and delete the disposable item. Keep the final trip page visible so create/read/update/delete are unambiguous. |
| 0:53–1:13 | Request an itinerary suggestion for the trip. Show the approved model/run identifiers and that the response is a draft requiring review before save. |
| 1:13–1:25 | Show the already-open Student 1 CI and AI-Mode CI successful runs; state that Compose/browser/Ollama evidence came from the current manual session, not from CI. |
| 1:25–1:30 | State one current limitation or degraded behavior and hand back to the group presenter. |
